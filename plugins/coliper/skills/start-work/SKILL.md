# `/start-work` - Durable Plan Executor

Use `/start-work` to execute implementation plans in `.coliper/plans/<slug>.md` sequentially with durable progress tracking and subagent orchestration.

## Overview
`/start-work` orchestrates execution of plans generated by `/ulw-plan`. It tracks progress durably across task boundaries using Boulder tracking state in `.coliper/progress.md` (and updates `.coliper/plans/<slug>.md`), invokes implementer and reviewer subagents for each step, and halts immediately if verification fails.

## Guidelines & Instructions

### 1. Plan Loading & Inspection
- Read the specified plan file from `.coliper/plans/<slug>.md` (or `<appDataDir>/brain/<conversation-id>/implementation_plan.md`).
- Parse all tasks and checklist items (`- [ ]`).
- Identify the first uncompleted task and verify prerequisite context.

### 2. Boulder Progress Tracking
- Maintain durable progress tracking state directly within `.coliper/plans/<slug>.md` and `.coliper/progress.md`.
- Mark completed tasks with `- [x]` only after verification passes.
- State persistence in `.coliper/` ensures execution can resume seamlessly across interruptions or new sessions.

### 3. Task Execution Sequence (MANDATORY SUBAGENT DISPATCH)
For each unchecked task in the plan:
1. **Dispatch Implementer (MUST call `invoke_subagent`)**: Call `invoke_subagent` with `TypeName: "implementer"` (or `"self"`) to execute the task using Test-Driven Development (TDD). Pass the task requirements, affected files, and verification commands.
2. **Run Verification**: Execute the task's specified test or build commands.
3. **Dispatch Reviewer (MUST call `invoke_subagent`)**: Call `invoke_subagent` with `TypeName: "reviewer"` to perform an empirical code review of the modified files and test outputs.
4. **Update Progress**: If verified by `reviewer`, mark checkbox `- [x]` in `.coliper/plans/<slug>.md` and record status in `.coliper/progress.md`.
5. **Halt on Failure**: If any step fails or tests break, halt execution, log error tracebacks, and report to user.

### 4. Subagent Orchestration
- MUST use `invoke_subagent` for all implementation and review phases (`implementer`, `reviewer`, `explorer`, `planner`, `momus`, `metis`).
- Maintain clear task boundaries and isolated contexts per subagent dispatch.

### 5. Completion Signal
- Continue executing sequentially until ALL checklist items in `.coliper/plans/<slug>.md` are marked `- [x]`.
- Once every task is empirically verified, output:
  `ORCHESTRATION COMPLETE`
