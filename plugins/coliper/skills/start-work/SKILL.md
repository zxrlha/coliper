# `/start-work` - Durable Plan Executor

Use `/start-work` to execute implementation plans in `plans/<slug>.md` sequentially with durable progress tracking and subagent orchestration.

## Overview
`/start-work` orchestrates execution of plans generated by `/ulw-plan`. It tracks progress durably across task boundaries using Boulder tracking, invokes implementer and reviewer subagents for each step, and halts immediately if verification fails.

## Guidelines & Instructions

### 1. Plan Loading & Inspection
- Read the specified plan file from `plans/<slug>.md`.
- Parse all tasks and checklist items (`- [ ]`).
- Identify the first uncompleted task and verify prerequisite context.

### 2. Boulder Progress Tracking
- Maintain durable progress tracking state in `.superpowers/sdd/<session>/progress.md` or directly within `plans/<slug>.md`.
- Mark completed tasks with `- [x]` only after verification passes.
- State persistence ensures execution can resume seamlessly across interruptions or new sessions.

### 3. Task Execution Sequence
For each unchecked task in the plan:
1. **Dispatch Implementer**: Invoke an implementer subagent to complete the task using Test-Driven Development (TDD).
2. **Run Verification**: Execute the task's specified test or build commands.
3. **Dispatch Reviewer**: Spawn the `reviewer` subagent to perform an empirical review of code changes and test outputs.
4. **Update Progress**: If verified, mark checkbox `- [x]` and record commit hash in progress log.
5. **Halt on Failure**: If any step fails or tests break, halt execution, log error tracebacks, and report to user.

### 4. Subagent Orchestration
- Use specialized subagents (`planner`, `reviewer`, `explorer`, `momus`) as appropriate during execution.
- Maintain clear task boundaries and isolated contexts per task execution.

### 5. Completion Signal
- Continue executing sequentially until ALL checklist items in `plans/<slug>.md` are marked `- [x]`.
- Once every task is empirically verified, output:
  `ORCHESTRATION COMPLETE`
